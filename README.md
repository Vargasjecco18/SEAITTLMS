# SEAITT-LMS

SEAITT Legazpi LMS, the learning management system of SEAITT (Senior High School, Legazpi). Blazor Web App on .NET 9 with a MySQL database,
set up without a `dotnet new` template and with its own login (no ASP.NET Core Identity package).

What exists so far:

- **A public home page** at `/` for visitors: photos of the school, its courses (read from the database) and a
  **Log in** button.
- **Custom login** with the school's picture next to the form: email + password, PBKDF2 password hashing, cookie
  sign-in, account lockout. **The sign-in ends 30 seconds after the last page of the system closed** (closing the browser or the tab, or going back out of the system; the cookie has no end date and there is no "keep me signed in" box; a refresh or the next page is fast enough to keep it). The person is then **offline at once** (the red dot) and has to log in again. Code: `Services/SessionWatcher.cs`, `SessionCircuitHandler.cs`. After signing in, everybody lands on the page of their role.
- **Users and roles**: Admin, Teacher, Student (with LRN), Registrar, Guidance Counselor, **Academic Coordinator** and **Academic Provider** (of the central team),
  each with its own table holding the person's name and details.
- **Registrar pages** (for the registrar only): *Dashboard*, *Enrollment* (the form that enrolls a student; the
  student's email and password are made automatically) and *Student's Accounts* (a searchable list).
- **Administrator pages** (for the administrator only): *Dashboard* (accounts, and who is **enrolled** or **not enrolled**) and *Users Management*: one list per role, with
  search, **edit**, **delete** and add (for staff).
- **Academic coordinator pages** (for the academic coordinator only): *Dashboard* (the stat cards, then **The school now** under them: the term that is on, its days and the numbers of the setup), *Academic setup* (school years, terms, tracks, strands, courses, class sections; tabs and cards), *Class sections*,
  *Teacher evaluation* (a questionnaire the students answer about their teachers), *Announcements* and *Analytics* (the results of the teacher evaluation).
- **Academic provider pages** (the central team; for the academic provider only): *Dashboard*, *Course library* (the syllabus and the handouts, **sent to the teachers** as drafts, and the **summative exams**, which have questions and the settings of a quiz and are **posted straight to the students**; the teacher makes the seatwork, assignments, quizzes and task performances), *Tracking* (the syllabus and handouts: did the teacher open it, post it, did the students open it; the summative exams: who opened and handed in; the teachers; the students) and *Analytics*.

Lessons, assignments and quizzes are next. The database design is in [docs/database.md](docs/database.md).

## Requirements

- [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)
- MySQL 8 with an empty schema named `seaittlms`, and a MySQL user that can create tables in it
- VS Code with the C# Dev Kit extension (recommended in `.vscode/extensions.json`)

## First-time setup

1. **Create your private settings file.** In the project folder, copy `appsettings.Local.example.json` to
   `appsettings.Local.json` (in VS Code: right-click the file, *Copy*, *Paste*, then rename the copy). Open it and
   replace the two placeholders:
   - `YOUR_MYSQL_PASSWORD` with your MySQL password,
   - `choose-a-long-password` with the password you want for the first administrator.

   Git ignores `appsettings.Local.json`, so your passwords never go to GitHub. **Never write passwords in
   `appsettings.json` or in `appsettings.Local.example.json`**: those files are committed and published (the example is
   only a template, the app does not read it). If a password ever ended up in a committed file, change that password.
2. **Run the app** in the project folder. In Development the tables are created automatically on startup:

   ```bash
   dotnet watch
   ```
3. Open http://localhost:5000. You see the public home page. Click **Log in** and sign in as
   **admin@legazpi.seaitt.edu.ph** with the administrator password from step 1. You land on the Administrator page.

If your MySQL uses another host, port or user, change the connection string in the same file. If the app says
**Can't connect to MySQL**, check the password in it, that MySQL is running, and that the `seaittlms` schema exists.

Other ways to give the app its passwords (the private file wins over all of them): `dotnet user-secrets set
"ConnectionStrings:Default" "..."` and `dotnet user-secrets set "Seed:Admin:Password" "..."`, or the environment
variables `ConnectionStrings__Default` and `Seed__Admin__Password`.

### The first administrator (seed account)

The first time the app starts on a database that has no administrator, it creates one: **System Administrator**,
email `admin@legazpi.seaitt.edu.ph` (the `Seed:Admin:Email` setting in `appsettings.json`), with the password you put
in your private settings file. To use other details, add them to the `Admin` part of that file before the first start:

```json
"Seed": {
  "Admin": {
    "Email": "principal@legazpi.seaitt.edu.ph",
    "FirstName": "Your",
    "LastName": "Name",
    "PhoneNumber": "09171234567",
    "Password": "choose-a-long-password"
  }
}
```

The seed only runs when there is no administrator yet, so changing these settings later does not touch an account
that already exists. The name and phone number are saved in the `administrators` table. To change the email of an
existing administrator, use **Users Management > Administrators > Edit** in the app, or run this in MySQL Workbench (emails are
stored in lower case):

```sql
UPDATE seaittlms.users SET email = 'admin@legazpi.seaitt.edu.ph' WHERE email = 'admin@seaitt.edu.ph';
```

### Creating and upgrading the tables

The app does it for you. Run `dotnet watch`: on a new empty `seaittlms` schema it creates every table, and on a
database from an older version it upgrades the tables **and keeps your data** (for example the names that used to be in
`users` are moved to the tables of each role). No SQL file is needed.

Prefer the command line? This does the same:

```bash
dotnet tool install --global dotnet-ef --version 9.0.20
dotnet ef database update
```

To see the tables as a diagram in MySQL Workbench use *Database > Reverse Engineer...* and pick `seaittlms`.

### Something broke? Start over

Use this when the database is broken, for example you dropped or changed tables by hand, an SQL script stopped halfway
("Table ... already exists" when the app starts), or MySQL Workbench shows *Error loading schema content ... Error Code:
1356 ... View 'seaittlms.v_...' references invalid table(s) or column(s)*. (An older version of the database had
`v_...` views that read `users` and the role tables, so they broke when those were missing or changed. The newest
version has no views.)

**Both ways erase all the data in `seaittlms`.** There is no undo.

**Quickest, needs only the app:**

1. In MySQL Workbench run `DROP DATABASE IF EXISTS seaittlms;`
2. Run `dotnet watch`. The app creates the database and every table again, and the administrator
   (`admin@legazpi.seaitt.edu.ph`, with the password from your `appsettings.Local.json`).

**Without running the app:** in Workbench open
[database/seaittlms_reset_and_rebuild.sql](database/seaittlms_reset_and_rebuild.sql) (*File > Open SQL Script...*) and
click the lightning bolt. It deletes the `seaittlms` schema and builds everything again, including the seven roles and
the school setup (school year, terms, tracks, strands, subjects). Then run `dotnet watch` to create the
administrator.

Any other users you had are gone. Add the staff again in **Users Management**, and the students by enrolling them.

**Sample accounts:** to get sign-ins to try the app (1 administrator, 1 registrar, 1 guidance counselor, **1 academic coordinator, 1 academic provider**, 12 teachers and 40 students), open
[database/seaittlms_sample_accounts.sql](database/seaittlms_sample_accounts.sql) in Workbench and click the lightning bolt.
It only adds what is missing (and gives the sample accounts of an earlier version the new email and password), so running it twice is harmless. The sign-in of each person is made from the
name and the number the person has at school, the same way the app makes the sign-in of a new person:

| Who | Email | Example |
|---|---|---|
| Administrator | `admin@legazpi.seaitt.edu.ph` | (the one the app made from `Seed:Admin`) |
| Staff and teachers | the last name, a dot and the digits of the **employee number** | `villanueva.001@legazpi.seaitt.edu.ph` (employee number T-001) |
| Students | the last name, a dot and the last 6 digits of the **LRN** | `jacinto.111111@legazpi.seaitt.edu.ph` (LRN 105202111111) |

The SQL files hold only the hashes of the passwords. The list with every sign-in (name, email and password of the 58 accounts) is in [docs/sample_login.md](docs/sample_login.md). A student's password is the last name followed by the same 6 digits, the rule the registrar's Enrollments page shows when a student is enrolled. These are sample accounts: give real people a harder password in **Users Management > Edit**.
(the registrar's Enrollment page shows it on the receipt when a student is enrolled; the form itself shows the sign-in details only until the courses of the strand appear); the list with every sign-in is kept out of the repository, ask for it when you need it. Give real people a harder password in **Users Management > Edit**.

The school has **one** administrator, registrar, guidance counselor, academic coordinator and academic provider, so the file never adds a second one and **never changes the password of the administrator you already have** (the last lines of the file, written as a
comment, can give that administrator the sample password too).

**Sample data:** the accounts have no courses or enrollments yet (the students are listed under *Not enrolled*). To fill the tables with practice data, run
[database/seaittlms_sample_data.sql](database/seaittlms_sample_data.sql) after the accounts file (open it in Workbench, press the lightning bolt, wait a minute or two). **Since the fix of round 36 it is a plain list of `INSERT IGNORE` and `UPDATE` lines** (about 16,000 rows, 172 statements): no variables, no temporary tables, no `IF`, nothing to type, so MySQL Workbench has nothing to trip on, and it can be run again (a row that is already there is skipped, nothing is added twice). It enrolls the 40 students in
**10 sections of 8 strands** (Grade 11 and Grade 12, the ACAD and the TECH-PRO tracks; one student has the name extension *Jr.*), gives the 12 teachers their courses, and adds, with dates around the day you run it (and **made from the data, not typed row by row**: see below): the library of the academic provider and what it sent to every teacher (some opened, some
still waiting, some posted), handouts with **PDF files** (the syllabus, the notes of the lesson, a worksheet and a rubric) and with the work the students handed in as PDF, assignments, quizzes with questions and task performances, who opened what, the work handed in and graded, attendance, announcements, messages, notifications, friends,
the automatic groups and three groups the students made, files in the lockers, the security log, the settings, announcements of every category
(an exam, a holiday, the semester break, a teachers' meeting, others, and two from a teacher to a class) and one teacher evaluation with every kind of question and its answers.
**The work in the sample data was generated, and it all connects.** The rows were worked out from what the school has (the earlier version of the file did it with SQL when you ran it; the file now holds the result as plain rows, written with times from the moment you run it: *3 days ago*, *5 days from now*), so nobody has to type them. Each student has a way of studying that always comes out the same for the same student (how well they do, how often they hand in on time, how often they come to class); two students (Carlo Alcantara and one more) struggle on purpose, so the guidance counselor has real cases. From that: every activity that is posted gets work from the students of the section (some on time, some late, some missing, some already handed in before the due date), only after its handout was posted and never in the future; a quiz or an exam is marked by the system from the answers of each student to its questions (`answers_json`; the score is the points of the questions answered right), and a few students leave the page (violations, and a flagged quiz when the system handed it in); the teacher has marked most of the rest and the newest waits for a score (a late one waits for the decision of the teacher); the attendance of the last four weeks is on three weekdays a week for each course, and a student who is absent is absent from every class of that day; a student opened every handout and activity they did (`module_views`, `item_views`) and the others opened part of them; the first posted lessons of every course have **slides** (a PDF of five slides) and each student who opened a lesson has read part of it (`module_reads`, the bar of the course page); the notifications (graded work, "due soon", "work waiting for a score") and the referral of Carlo (his grade in Business Accounting) are read from that work. The temporary tables of the file are dropped at the end. **Every table has sample rows** (round 35): besides the work above, the file adds the achievements the students earned (from their work), the personal calendar (a teacher plans to check the scores, a student starts a task performance early, the coordinator's meeting with the teachers invited, the guidance counselor's talk with Carlo), two custom roles, the final grades of one course out of four (the grade the scores add up to), a holiday the coordinator took off the calendar, the sound of the school and a sound of one student (small WAV files), profile pictures (small PNG files) for the staff, the teachers and about half of the students, and three courses of the library marked Complete. To start over: run the reset file, then the accounts file, then this one.

Only want to clear the Workbench error without erasing anything? Run this in Workbench (it only drops the five old views,
and does nothing if you don't have them):

```sql
DROP VIEW IF EXISTS seaittlms.v_administrators, seaittlms.v_guidance_counselors, seaittlms.v_registrars,
                    seaittlms.v_teachers, seaittlms.v_students;
```

If Workbench stops an SQL file with *Error Code: 1175 ... safe update mode*, your copy of the file is old: pull the
latest version (current files work with Workbench's default settings).

The reset file is generated from the migrations, don't edit it by hand. After a schema change, regenerate it with
`bash database/export-schema.sh` (on Windows, in Git Bash; it needs the `dotnet-ef` tool and a running MySQL).

### Production

Set `ConnectionStrings__Default` and `Seed__Admin__Password` as environment variables (and `Seed__Admin__Email` if
you want a different one) and run `dotnet ef database update` (or `Database__MigrateOnStartup=true` for the first
start). Don't copy `appsettings.Local.json` to a server. The sign-in cookie is https-only outside Development.
Persist the ASP.NET Core Data Protection keys if you run in a container.

## Everything keeps up by itself (no F5)

- **Messages and notifications** arrive at once: when somebody sends a message or something happens for you, the number on the Messages button, the bell and
  the open conversation change by themselves (`Services/LiveUpdates.cs` tells the pages that are open; they also look again every 5 to 10 seconds, in case the news
  came from somewhere else).
- **The dashboards, the calendar, the lists of courses, the grades, the analytics and the registrar's student list** look again every 30 seconds
  (`<AutoRefresh />`, the script at the end of `wwwroot/app.js`). It only changes what is different, keeps the place on the page, and waits while you are typing, a pop-up is
  open or the tab is hidden. The calendar, due dates and announcements in the column at the right look again every 30 seconds too.

## Who sees what

After signing in (and whenever a signed-in person opens `/`), the app sends everybody to the page of their role
(`Auth/RoleHome.cs`). A page that a role may not open shows *Access denied*. The menu only lists what the role can open.

| Role | Lands on | Can open |
|---|---|---|
| Admin | `/admin` | Dashboard (with **Enrolled** and **Not enrolled** under *Accounts*), **Users Management**, **Archive Accounts**, **Analytics**, **Security Logs**, **Database Backup**, **System Settings** |
| Academic coordinator | `/coordinator` | **Dashboard**, **Academic setup**, **Class sections**, **Teacher evaluation**, **Announcements** (a calendar), **Analytics** (teacher evaluation), **Calendar**, **Users**, **Groups**. It no longer sends course materials. |
| Academic provider (central team) | `/provider` | **Dashboard**, **Course library** (and sending), **Tracking** (Syllabus, Handouts and Summative exams), **Analytics** |
| Registrar | `/registrar` | Dashboard, **Enrollment**, **Student's Accounts** |
| Teacher | `/teacher` | **Dashboard**, **Courses** (handouts, assignments, quizzes, task performances, grading), **Attendance**, **Calendar**, **Announcements** (to their classes), **Gradebook**, **Analytics**, **Users**, **Groups**, **Resources** (in this order in the menu) |
| Student | `/student` | **Dashboard**, **Courses** (handouts, work, quizzes), **Calendar**, **Grades**, **Users**, **Groups**, **Resources** (in this order in the menu) |
| Guidance counselor | `/guidance` | **Dashboard**, **Referrals** (one row for each student), **Analytics** |
| A role made by the administrator (for example *Librarian*) | `/staff` | Its own dashboard with the pages that were ticked for the role (Calendar, Users, Groups and the analytics), nothing else |

Every role also has **Help** (`/help`, the link above the profile card in the menu): the answers to the usual questions of the role, with the steps.

There is no "My account" page: people sign in, work, and sign out. Somebody whose role has no page of their own (it should not happen) is sent to *Access denied*.

The registrar pages belong to the registrar: **an administrator cannot open them**. To get a registrar, sign in as the
administrator, open **Users Management > Registrars**, press **Add registrar** and give the person an email and a first
password. Then sign in as that registrar to enroll students.

**Round 40: the roles with ticked pages.** (Round 41 took the Admission role and the student application out again: no role id 8, no `admission_officers`, `student_applications` or `application_files` tables, no application form on the home page. The migration `RemoveAdmission` deletes the accounts of that role.) The administrator makes a staff account in **Users Management > Staff > Add staff**: the employee number starts with the first letter of the role.

A **role the administrator makes** (type a new name in *Name of the new role*) shows the **pages as checkboxes, one by one**: Calendar, Users, Groups and the analytics (school, guidance, library, evaluation). The pages are saved in `custom_roles.pages` (migration `AdmissionAndRolePages`), the person signs in as an academic provider underneath (the base role keeps the account working) but carries the claims `RoleTitle` and `Pages` (`Auth/AppClaimTypes.cs`), lands on `/staff` (`Components/Pages/Staff/Home.razor`, cards for the ticked pages) and the layout (`MainLayout`) shows *Access denied* on any page that was not ticked (`Services/StaffPages.cs`: `StaffPages.All` is the catalog, `StaffAccess.Allows` is the guard). **Round 41:** the pages of the other staff roles can be ticked too: `StaffPages.All` has the registrar (dashboard, Enrollment, Student's Accounts), the guidance counselor (dashboard, Referrals), the academic coordinator (dashboard, Academic setup, Class sections, Teacher evaluation, Announcements) and the academic provider (dashboard, Course library, Tracking) next to Calendar, Users, Groups and the analytics; each page has an `Area` (and `Exact` for the dashboards). A person who has a page of an area gets the **role of the area** as an extra role claim besides the base role (`AuthService.CreatePrincipal`, `StaffAreas.Of`), so the page's `[Authorize(Roles = ...)]` opens, and the services check the database with `StaffAreas.InArea(...)` (the role itself, or a made-up role with at least one page of the area) at the moment of saving (`EnrollmentService`, `ReferralService`, `SchoolSetupService`, `SetupWorkbookService`, `EvaluationService`, `AnnouncementService`, `CalendarService`, `StudentLifecycleService`, `SystemSettingsService`); `CurrentUser.GetInAreaAsync` gives the coordinator pages the person as a coordinator. **The pages of the administrator can't be ticked**, and there is no *Remove role* button any more (the people keep the role; round 41). The layout still shows *Access denied* on any page that was not ticked (the claims are read at sign-in: a role that is changed reaches the people who sign in after that).

## Courses, handouts and work

(In the app the subjects of the school are called **courses**. The database tables keep the name `subjects`.)

**The administrator** gives each teacher their courses: **Users Management > Teachers > Courses**, choose the section and
the course (only the courses of that section's strand are listed). A course of a section has one teacher. A new teacher can get
their track, strand, section and courses right away in the **Add teacher** form (see *Users Management* below).

**Teacher > Courses** shows one colored card per course (a teacher with more than one section also gets a chip per section to show one
section at a time). The two buttons at the right of the chips **change the view**, like the student's page: **Cards** (with the calendar at the right) or a **List** (course, section,
students, **Handouts** (posted, with a bar) and **Work** (the assignments, quizzes and task performances, with a **"2 to check"** button that opens a box with the work handed in and not scored yet, each one a link)). A card has the same look: the photo of the strand, the course, the **section** and the **class time** one under the other at the left, then the counts of **handouts (with how many are posted), assignments, quizzes and task performances**, and a *to check* badge when something waits to be scored. **Open** shows its handouts.

**Inside a course (teacher and student) there is a second menu** (at the left of the page, above it on a phone): **Handouts** (the page that was there before), **Assignments**, **Quizzes** and **Task performances** (each opens the list of that kind for the whole course, handout by handout, with a count), and the pages that belong to the course: for the teacher **Attendance**, **Gradebook** and **Students** (the students of the course, each with a **Message** button that opens the messages on that student), for the student **Grades** and **Teachers** (the teacher of the course, with a **Message** button); **Exams** joins the student's menu once the course has a summative exam; **the teacher's menu has no Exams and a teacher can't add an exam** (the summative exams are the academic provider's; the server refuses one: `ModuleService.SaveItemAsync`). The school's own menu stays as it is. **The menu can be hidden and shown**: its first button (*Hide menu* / *Course menu*) folds it away so the page takes the whole width, and the choice is kept on that computer (`data-course-menu` on the page, kept in the browser). **It stays in view under the header while the page scrolls** (on a phone it is a strip under the header), so *Handouts* is always there. It is on the course page, on the lesson a student reads (**Read lesson** and **Read again**) and on the handout page of the teacher. **On those two reading pages the school's main menu folds to its icons** (a narrow column; the first button of the column shows the names again, and the next page has the full menu back): `Components/Shared/CourseLayout.razor` (`CollapseMenu`) puts a marker, `wwwroot/app.js` sets `data-rail` on the page and the width comes from `--sidebar-w` (`App.razor.css`, `MainLayout.razor.css`). The teacher's handout page has no *Lesson* card: the lesson text is in **Edit handout** at the right. **Reading progress.** On the handout page (teacher and student) the title has a **Read N%** bar. It counts only what happens **inside the files of the handout**: a PDF is drawn page by page in the page itself (PDF.js, `wwwroot/lib/pdfjs`), and the bar grows with **the pages that were in front of the reader for a moment** and **how far the reader scrolled inside the PDF** (half and half); a sound or a video counts for the part that was played, a text file for how far it was scrolled, a picture for being looked at. **Scrolling the rest of the page counts for nothing.** Each file is an equal share of the bar, the bar never goes back, and what was read is kept in the browser for each handout. A PDF has a "Page 3 of 12" badge; "Open in a new tab" opens it in the browser's own viewer (print), and Download saves it. Code: the reading block of `wwwroot/app.js`, `Components/Shared/FilePreviewPane.razor`, `ReadProgress.razor`. **On the course menu every kind ends with an "Add seatwork" (and so on) line for the teacher**, also when the kind already has activities (it opens the list of that kind with its Add menu open). **On an activity page the student has a Course menu button in the title** (the same menu in a pop-up, with the open activity marked), and the teacher's activity page has **View activity** at the right of the title: it opens what was given (the instructions and the files) in a box in the middle of the screen. *(The small **Activities** pop-up of rounds 31 and 32, at the left of *Add activities*, was taken away in round 34: the Course Menu lists the activities by kind, each one a link, with an **Add** line for each kind.)* **On the results of an activity the column is called *Answers*** (the answer and the files of each student as small tags; there is no arrow at the end of the row): **press the row or a tag** and a wide box opens with **the students who handed in at the left** (press one to see theirs), **the answer in the middle with a preview of the files the student sent** (a PDF, a picture, a text file, a sound or a video are shown right there) and **the score and the feedback at the right** (`ItemSubmissions.razor`, `FilePreviewPane`). The tab is in the address (`?tab=assignments`, `quizzes` or `tasks`). Code: `Components/Shared/CourseMenu.razor`.

**Add activities** (top right of a teacher's course page; the provider's library has its own buttons: *Add syllabus*, *Add handout*, *Send to teachers* and *Add summative exam*): since round 33 it opens a **sheet inside the system**, in the middle of the screen with the step by step at the right (no Excel file): a row for each activity with its **Handout** and **Type** (lists to choose from: Seatwork, Assignment, Quiz, Task performance), **Title**, **Instructions**, **Points**, **Due date** and **Files**; a new row starts in the handout of the row above, the *Ready* column says what is missing, a row with nothing in it is ignored and *Save* puts every ready row in its handout like the box of the page does. **The recitation is not an activity of the course**: it is only a column of the gradebook. ## Graduation (archive)

**The archive is automatic.** When the **last term of a school year has ended** (the day after its last day, Philippine date), the system archives, by itself, every grade 12 student who was enrolled in that term: they are marked *Graduated*
with the note "Graduated: <term> ended (automatic)", their enrollments are completed, referrals end and their sign-in is switched off. It runs in the background job every minute, is safe to repeat, and writes one line in the Security Logs
(*Students archived*). Code: `StudentLifecycleService.ArchiveFinishedAsync`. The page below is still there to archive somebody earlier, and to restore.

**Administrator > Archive Accounts**: the grade 12 students who are still at school are listed. Tick the ones who graduate (or **Select all**), add a note

records stay. The *Archived* tab lists the graduates and can **Restore** one (the account works again; the registrar enrolls
the student again for a class). A student in the archive can't be enrolled until an administrator restores the account.

**Security Logs** (`/admin/security-logs`) has a **Last login** list (each person, their role and **the day and time they last logged in**, newest first, with a search and a role choice; there are no "signed in" and "signed out" lines any more) and lists who typed a wrong password (and from where), locked accounts, accounts that were added, changed, switched off or deleted, new passwords, backups and changes

**Database Backup** (`/admin/backups`) saves a copy of **all the data** as an SQL text file in the `Backups/` folder next to the app (git ignores it), made from one consistent snapshot of the database.
*Back up now* makes one; each backup can be **downloaded** or **deleted**; a backup file from another computer can be **uploaded**. **Restore** asks you to type `RESTORE`, first makes a safety backup of what is there now,
checks that the file is one of ours (only our tables and plain statements are accepted), puts the data back while the system is closed to everybody except administrators, and **goes back by itself** if something fails.
An automatic backup at an hour you choose (and how many to keep) is set in System Settings. Code: `Services/BackupService.cs`, `MaintenanceWorker.cs`.

**System Settings** (`/admin/settings`) changes, without editing files: **maintenance mode** (while it is on only an administrator can use the system; everybody else sees a page with your message), and
the **automatic backup** (the hour and how many to keep), how long the **log** is kept, **Files and lockers** (the biggest **file**: 200 MB at first, from 1 to 1000; the files of a handout, the slides and the Excel files have **no limit in MB**; the size of each person's **locker**: 500 MB at first, from 10 to 50000) and **the sound of the school** (an .mp3, .ogg, .wav or .m4a of up to 2 MB that plays for everybody who has not chosen another; it can be removed). Files are kept in the database as one piece, so MySQL must accept a packet that big (`max_allowed_packet`): the system raises it by itself at start when the database user may (`SET GLOBAL`), and System Settings warns when the value is too small for the size chosen; otherwise set `max_allowed_packet=1G` in `my.ini` and restart MySQL. (The number of students a section can have is not here: the academic coordinator sets it in *Academic setup > Class sections*, **Students in one section (the limit)**.) Every change is written in the security log. (The other values the system uses, the name of the school, the wrong passwords before a
lock and the minutes locked keep their usual values; they are in the `system_settings` table if you ever need to change one.)
Code: `Services/SystemSettingsService.cs`; the values are kept in the `system_settings` table and read once when the app starts.

posted. `/files/a/<id>` sends the file; `?download=1` always saves it. **A click on a file name never saves it by itself: it opens a box in the middle of the screen** (`Components/Shared/FileViewer.razor`, in the main layout; `wwwroot/app.js` fills it) that shows a PDF, a picture, a sound or a video, or says that the file can't be shown here; the box has **Download**, **Open in a new tab** and a close button (Escape closes it). Only the people who may see a handout can open its files. Code: `Services/AttachmentService.cs`,
`Components/Shared/AttachmentList.razor`, `AttachmentPicker.razor` (tables `attachments` and `attachment_contents`).

## Academic coordinator: teacher evaluation and analytics

**Teacher evaluation** (`/coordinator/evaluations`): each evaluation has **Open** and, **at its right, Copy**: it makes a new draft *Copy of ...* with the same instructions and questions (nothing is sent, and the answers are not copied) and opens it to be changed. **New evaluation** starts with the usual 16 questions about a teacher in areas such as *Teaching* and *Classroom management*; the coordinator changes,
adds, copies and removes questions while it is a draft. A question is added by choosing **how the students answer**:

| Kind | The students see |
|---|---|
| 5-Point Likert Scale | Strongly disagree, Disagree, Neutral, Agree, Strongly agree (1 to 5) |
| 5-Point Performance Scale | Poor, Fair, Good, Very good, Excellent (1 to 5) |
| Frequency Scale | Never, Rarely, Sometimes, Often, Always (1 to 5) |
| Binary Scale | Yes or No |
| Ranking Scale | The options the coordinator wrote (2 to 10), each given its own place |
| Select-All-That-Apply | The options written (2 to 10), tick every one that fits (none is fine) |
| Comment | A few words |

The three 5-point scales make a teacher's **average** (at least one is needed); Yes/No, rankings and select-all questions have their own results in the analytics (the share of Yes and No, the average place and
how many put an option first, the share who ticked each option). **Send to students** picks the teachers' courses it is about and a **due

### The automatic email and password

A student who is not in the system yet gets an account made from the last name and the **last 6 digits of the LRN**:

| | Rule | Example (LRN 111111111111, "Jecco seth C. Vargas") |
|---|---|---|
| Email | `lastname` + `.` + last 6 digits + `@legazpi.seaitt.edu.ph` | `vargas.111111@legazpi.seaitt.edu.ph` |

## How the login works

1. `/login` is a normal form. `AuthService` looks the user up by email, checks the password hash and the lockout,
   and the page writes the sign-in cookie.
2. Every page needs a signed-in user unless it has `@attribute [AllowAnonymous]` (the public home page, the login page and
   the error pages have it). Restrict a page to roles with `@attribute [Authorize(Roles = AppRoles.Admin)]`
   (an administrator and a registrar each have their own pages: neither can open the other's). A signed-in user who opens a
   page they may not see gets an *Access denied* page.
3. Wrong passwords are counted. After 5 in a row the account is locked for **5 minutes** (the `Auth` section in `appsettings.json`; the administrator can change both numbers in *System Settings*, and a number saved there wins). The lock runs from the **5th wrong try** (not from the first one), and while it lasts even the right password is refused. The login page then shows a **box over the email with a timer** (*Try again in 09:42*) that counts down by itself and says when the time is over; the timer is still there if the page is opened again. **The timer is a lock of that browser:** while it runs, no sign-in is accepted from it, with any email and any password (even the right one, and even the right one of another account), and the password is not looked at; the account also has its own lock in the database, so another browser is refused too. (On a shared computer, the next person waits for the timer as well.) An **email with no account** is answered with **User Not Found** (it is not counted and does not lock; the page is the same for every role). The moment the lock ends is kept in `users.lockout_end_utc`; the administrator can also unlock an account in *Users Management*.
4. A signed-in user is re-checked against the database every few minutes, so deactivating an account (or changing
   its `security_stamp`, which editing the email or password in **Users Management** does) signs it out.
5. **One sign-in at a time for an account.** While somebody is using an account in a browser or on a device, signing in with it somewhere else is refused: the login page shows an alert at the **top center** (*Can't log in, someone is logged in. This account is signed in on another device or browser ...*) and the form stays as it was. The open sign-in is kept in `users.active_session_id` (its number is also in the sign-in cookie) and `active_session_seen_utc`: every page that is open says it is still there once a minute, so a browser that was closed without *Log out* frees the account after `Auth:SessionIdleMinutes` (3). *Log out* and a password change free it at once. If the account is signed in somewhere else after an old sign-in was not seen for a while, the old page notices by itself, signs out and the login page says *You were logged out*. Turn the rule off with `Auth:SingleSession: false`. (A browser that is signed in already, opening `/login` again, is sent back to its page with the alert *Somebody is already signed in on this browser*.) Code: `Auth/AuthService.cs` (`LoginAsync`, `TouchSessionAsync`, `EndSessionAsync`), `AuthCookieEvents.cs`, `Components/Shared/TopAlert.razor`.
6. **Login code (OTP, round 42):** see *One-time code (OTP) with UniSMS* below. It is off until an administrator turns it on in *System Settings*, and for now it is asked from **administrators only**.
8. **Back button and forwarded ports (round 39).** Opening `/login` while already signed in sends the person to their dashboard **quietly** (no *Can't log in* box: that box is only for a second sign-in on another device), and the pages are sent with `Cache-Control: no-store`, so **Back** asks the server again instead of showing an old login page. Every redirect the server makes while a page is drawn (`Login`, the home page `/`, `/maintenance`, and the redirect of a page that needs a sign-in or a role: `AccessDenied`/`LoginPath` in the cookie handler) is a **relative** address (`/teacher`, `/login?returnUrl=...`), because a server reached through **a forwarded port** (the *Ports* tab of VS Code, a dev tunnel, a reverse proxy) only knows `localhost:5000` and an absolute address built from it opens nothing on the computer of the person. `Program.cs` also reads `X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host` (`UseForwardedHeaders`, trusted from any proxy; set `Hosting:TrustForwardedHeaders` to `false` in `appsettings.json` to switch it off) so the addresses and the cookie's Secure flag follow the address the person used.
7. **Away from the keyboard (round 41).** The message that logged a person out after 30 minutes without doing anything was taken out (`IdleWarning`, `AfkWarnMinutes` and `AfkLogoutMinutes` are gone): a person who is away with the page open stays signed in. Closing the browser still ends the sign-in (`SessionIdleMinutes`, see rule 5 above).

**Round 40: closing the browser and the back button.** Closing the browser, or going back to `/login` while signed in, ends the session without a countdown: the login page signs the person out, and a signed-in session ends **10 seconds after the last page of the person was closed** (`SessionWatcher.Grace`; the 2-second tick of `SessionCircuitHandler` is what notices), so a reload or a move to another page does not sign anybody out. After the sign-in the page that was wanted (`returnUrl`) is only honored when the same person signs in again **and** the page belongs to their role (`LocalUrl.IsPageOf`): the old bug where another person was sent to a course that was not theirs (*Course not found*) came from that.

## One-time code (OTP) with UniSMS

An administrator who types the right email and password also types a **code of 6 digits** that [UniSMS](https://unismsapi.com) sends to the phone number of the account (sender id **Unisoft**; the message is *"SEAITT Legazpi LMS: your login code is 123456. It expires in 5 minutes. Never share this code with anyone."*). The sign-in is finished when the code is typed. **Only administrators are asked** (a trial; the teachers, the students and the staff sign in as before), and **only while the switch in System Settings is on** (it starts off).

**To use it on your computer (nothing secret goes in the repository):**

1. **Put the API key in your private settings.** In the project folder (where `SEAITT-LMS.csproj` is), in a terminal (Git Bash or the VS Code terminal):
   `dotnet user-secrets set "UniSms:ApiKey" "PASTE-YOUR-KEY-HERE"`
   (or, instead, copy `appsettings.Local.example.json` to `appsettings.Local.json`, which git ignores, and write the key under `"UniSms": { "ApiKey": "..." }`). The key is the one of the API **SEAITT LMS Authentication** in the UniSMS dashboard. **Never write it in `appsettings.json`, in a `.cs` file or in a commit.** The sender id (`Unisoft`) and the address of UniSMS are in the `UniSms` section of `appsettings.json` (they are not secret).
2. **Start the app again** (`dotnet watch`), sign in as the administrator and open **System Settings > Login code (OTP)**: type your phone number in *Phone number of your account* (like `09171234567`; it is saved as `+639171234567`) and press **Save my number**.
3. The card says whether UniSMS is set up and whether your account has a number. Press **Send a test message to my phone**: a message must arrive. Then tick **Ask administrators for a code when they log in** and **Save settings**. (The switch can't be turned on while the key or the number is missing.)
4. Log out and log in: after the password, the page asks for the code.

**How it works.** `Services/UniSmsClient.cs` sends one POST to `https://unismsapi.com/api/sms` with the JSON `{"recipient": "+639...", "content": "...", "sender_id": "Unisoft"}` and the key in the `Authorization` header (`Basic`, the key as the user name and an empty password; `UniSms:AuthScheme` can be `Bearer`). The names of the fields and the address are in `UniSmsOptions` (`Auth/UniSmsOptions.cs`) so they can be changed in the settings if the UniSMS documentation says otherwise; an answer that is not 2xx is shown to the administrator with its status and its reason (never with the key). `Auth/OtpService.cs` makes the code (a random number, never typed by anybody), keeps **only a hash** of it in the table `login_otps` (with a hash of a random token that the browser keeps in the cookie `seaitt_otp` while it waits), and checks it: **5 minutes**, **5 wrong tries** (then the code is cancelled and the person types the password again), **a new code after 60 seconds** (4 codes at most for one sign-in), a sign-in that waits more than 15 minutes is forgotten, and a good code can be used **once**. These numbers are in the `Otp` section of `appsettings.json`. `AuthService.LoginAsync` stops after the right password and returns `LoginFailure.OtpRequired`; `AuthService.CompleteOtpAsync` finishes the sign-in (one sign-in at a time, the day of the last login) when the code is right. No message is paid for when the password is wrong or the account is in use somewhere else. The security log has *Code sent*, *Wrong or expired code* and *Code accepted* (never the code or the key).

**If something is missing.** If the switch is on but the key or the number of the administrator is missing, the administrator signs in with the password only and the log says *Signed in without a code* (a missing setting can't lock the only administrator out). If UniSMS **can't send** the message (no credit, no internet), the administrator can't finish the login. To open the door again, in MySQL Workbench run `UPDATE system_settings SET value = '0' WHERE `key` = 'signin.otp_enabled';` (the app reads the settings when it starts: start it again).

**Please check the request against the UniSMS documentation.** The sandbox where this was written can't reach `unismsapi.com`, so the request above (address, `Basic` key, field names) was written from the UniSMS documentation as it was remembered and tested only against a **fake** UniSMS (`b42tests`, `t_b42.js`: the tests check the exact request that is sent). The *Send a test message* button is the real test: if it says `UniSMS answered 401` the key or the `AuthScheme` is wrong; `404` the address; `400` or `422` the names of the fields or the sender id (it must be registered in UniSMS); the reason UniSMS gives is shown next to the status. Tell me what it says and the code is changed in a minute.

The API key was pasted in a chat: **create a new key in the UniSMS dashboard** and use that one (the old one can be deleted there).

## The sound of the notifications

**The sound of a notification.** A short sound plays when a new message or notification arrives while a page is open. **Each person chooses it in Settings** (*Notification sound*: two tones, chime, bell, pop, knock, the sound of the school, or **their own file** that they add there; the choice is kept in `users.notification_sound_choice` and the files in the table `notification_sounds`: one row per person, and one with no person for the school, which the administrator adds in System Settings). The files are served by `/account/notification-sound` (the person's own) and `/account/school-sound` (the school's) to signed-in people only (`Services/NotificationSoundService.cs`). A browser keeps sound off until the person has clicked or typed on the page once; when a sound cannot play for that reason a small button *Turn on the sound* appears, and one click turns it on. With no choice and no school sound, a file called `notification.mp3` (or `.ogg`, `.wav`, `.m4a`) in `wwwroot/sounds/` is played if it exists; without it, two short tones that the browser makes are played. The system can't take a sound from a YouTube video by itself (that is not allowed and the site has to be reached); download a sound you may use and save it in that folder (see `wwwroot/sounds/README.txt`).
